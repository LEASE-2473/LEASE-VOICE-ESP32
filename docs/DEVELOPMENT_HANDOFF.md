## 固件内部边界

建议在一个 ESP-IDF 工程中划分以下职责，目录名由开发侧根据实际实现确定，不将规划写成已有代码：

1. 板级配置：集中保存目标板、内存配置、引脚及来源；驱动不散落硬编码。
2. 网络配置与连接：本地配网、凭据保存、Wi-Fi 连接及重连；向其他模块提供网络状态。
3. BLE 配网：后续通过 BLE 设置网络，复用同一个网络配置模块。当前蓝牙范围按 BLE 配网规划，尚未验收，不承诺普通蓝牙音箱功能。
4. 音频输出：I2S、音量、停止、低音量测试音；第一版不依赖屏幕、麦克风或真实 TTS 服务。
5. 设备服务：实现调试 v1 HTTP API，调用网络和音频模块；后续接入单独确认的音频传输协议。
6. 屏幕与按键：显示连接/播放状态、处理本地操作；屏幕异常不阻断基本联网与日志。

TTS provider 凭据和云端合成继续留在电脑端。调试协议以 shared/protocol/README.md 和 device-debug-v1.schema.json 为准：GET /lease-voice/v1/info；POST /lease-voice/v1/command 支持 test-tone、stop、volume。设备 Token、能力声明和失败响应必须按实现核对；尚未实现的能力不得声明支持。

## 里程碑与验收顺序

| 阶段 | 开发交付 | 本聊天实物验收 |
| --- | --- | --- |
| M0 构建与启动 | 可复现构建、版本号、启动日志、内存检查 | 烧录后启动稳定；日志容量与实物一致，无重启循环 |
| M1 独立基础功能 | Wi-Fi 配置/保存/重连；单独的低音量测试音入口 | 能获取 IP、断电后恢复网络；喇叭测试音、停止与音量有效 |
| M2 设备调试 | 对齐现有 HTTP 调试 v1，提供凭据配置方式 | 从电脑访问 info；插件检查连接、测试音、停止、音量通过；错误 Token 被拒绝 |
| M3 语音播放 | 双方先明确音频传输、格式/解码、任务取消及错误协议，再实现 | 先本地测试音频，再真实 TTS；检查连续播放、停止、断网及重试 |
| M4 易用性与屏幕 | BLE 配网、已确认型号的屏幕和状态提示 | 新网络配网、失败恢复、屏幕状态与播放一致 |

用户于2026-11-02明确要求减少等待与重复验证：M0实际启动和内存通过，观察26条心跳至260秒均PASS/堆稳定后即推进；剩余长观察与三次断电测试不作为后续开发前置条件，也不宣称已执行。只在新变更、失败或具体疑点时追加检查。

每阶段均区分“编译通过”“模拟通过”“实物通过”。M1 的网络与测试音可独立开发，问题互不阻塞；BLE 不作为首个联网版本的前置条件。首版 Wi-Fi 配置方式由开发侧明确实现，凭据不得进入发布包、源码、聊天或日志。

## 每次固件交付必须包含

- 唯一版本号和独立产物目录，交付后不覆盖正在验收的版本；可使用 firmware/esp32-s3/artifacts/<版本>/。
- 实际 ESP-IDF 版本、目标芯片、内存配置、依赖和完整构建命令，以及执行结果。
- 每个 .bin 的 SHA-256、大小、烧录地址及来源；给 Flash Download Tool 使用的完整参数或可核对的烧录清单。不得凭经验猜地址。
- 必须注明是合并镜像还是分离镜像、是否保留网络配置、是否涉及分区变更。默认升级不整片擦除；确有必要时说明数据影响。
- 启动日志波特率、预期日志、配置入口、IP 获取方式、本次验收步骤、已知问题。
- 上一已验证版本的回退方法；首版不存在已验证版本时明确说明，无原固件备份不得声称可恢复出厂固件。

当前聊天在烧录前核对版本、校验值、地址和参数，并评估是否需要备份原 Flash。一次只运行一个串口工具；串口监视器必须在烧录前关闭。开发聊天只能编译交付，不触碰实物。
