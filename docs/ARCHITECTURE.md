## 1. 产品边界

插件在输出侧做语音、完成提示与独立素材播放。文本来自 DSH 已生成的助手回复，不重新问 LLM、不生成朗读提示词、不改聊天正文。配置音色、语速属于 TTS 参数，不是聊天提示词。

软件与固件在同一项目中独立构建、独立发布；DSH 插件包不携带固件工具链、第三方原始素材或个人运行数据。每次开发仅维护根目录的一套连续性文档。

## 3. 第一阶段：可独立使用的 TTS

### 使用与配置

- 每条已完成助手回复提供“转语音”按钮；合成后可以播放、停止、重播，失败显示可重试错误。
- 语音设置页配置 provider、endpoint、凭据、模型、音色，以及 provider 实际支持的语速/格式等参数；提供独立试听。
- 支持多个 provider 配置档，选择一个活动档；首版先把一个实际服务打通，不能将任意 HTTP 地址当作通用 TTS 协议。
- 模式为“手动”与“自动”，默认手动；自动模式只处理启用后当前选中主会话的新最终回复。新任务进入同一输出队列，默认顺序播放，用户可以停止并清空待播队列。
- UI 展示合成中、待播放、播放中、完成、取消、失败及“需要点击启用声音”。模式切为手动时取消未开始的自动任务，停止正在进行的自动合成/播放；手动重播不受自动去重阻拦。
- 不因页面加载、历史回放、切换会话或刷新而自动补读旧消息；切换会话停止旧会话本窗口播放并释放自动播放资格。

### 文本与事件

```text
主会话最终助手消息
  → 提取正文中的文本块
  → 确定性整理 Markdown / 按长度分段
  → 后端合成任务 → TTS adapter → 音频产物
  → 输出队列 → 浏览器播放器
```

消息按钮通过 DSH 的 `conversation.chat.assistant-actions` 插槽接收 durable messageId；宿主按会话与消息身份读取正文并校验访问权限。自动模式结合 `session/event` 中的 `assistant/message` 与 `turn/end`，实现前须核实结束原因和最终消息投影；不是每次 assistant/message 都等于最终答复。

默认只朗读成功回合的最终助手答复；忽略子代理、内部后台任务、工具结果、reasoning、失败/中断片段和空内容。手动只操作对应完整消息。工具执行前的中间发言不自动朗读；同一最终回复若由多个正文片段组成，按宿主最终投影的顺序处理，禁止跨步骤猜拼。

文本处理保留自然语言及段落，移除 Markdown 标记；默认跳过代码块、图片标记与链接 URL、保留链接文字。不下载或理解附件，不回写聊天内容。处理后为空时提示“没有可朗读文本”。长文本按段落/句子与 provider 限制分段，保序、可取消，不静默截断。

### 任务与输出

- TTS adapter 接收文本、模型、音色与支持的参数及取消信号，返回有明确 MIME/编码/采样信息的音频；扩展能力由 adapter 声明。
- 合成任务与播放任务分开。取消后迟到的音频不得启动播放；失败不无限重试、不触发额外聊天调用。
- 自动任务身份包含会话、消息、正文版本和输出目标；缓存另包含整理后的文本、provider 配置版本、模型、音色及音频参数，避免换音色仍播旧缓存。
- 一个浏览器客户端持有会话的自动播放租约，避免多窗口重复收费/发声；后端合成去重不能代替客户端播放协调。租约过期、断线重连与手动重播分别处理。
- provider 密钥仅宿主侧持久化；前端配置脱敏、修改显式提交，日志不记录密钥和完整聊天正文。音频通过受保护接口读取；缓存设容量/有效期并支持清理。
- 浏览器必须经过一次用户手势启用声音；被阻止时显示操作按钮，不把合成成功等同于播放成功。

### 阶段验收

先实现手动按钮和一个 provider，再补自动模式、队列与多窗口协调。

必须验证：真实 provider 可试听与朗读；取消/重播/失败恢复；长文本与空正文；工具多步和思考不会误播；刷新不重复播放；双窗口不重复自动合成/播放；浏览器授权提示正确。mock 负责稳定边界测试，真实服务验证单独记录。

## 4. 原生 DSH 与 WRX 兼容性

| 层 | 已知事实 | VOICE 的处理原则 |
| --- | --- | --- |
| DSH 接口 | 本机安装包类型声明包含消息操作栏与会话事件 | 通过适配层使用，运行行为仍须隔离验证 |
| LEASE-WRX 插件 | 请求编排、历史窗口、素材快照、记忆及预设 | 不依赖其数据、API、请求改写或配置 |
| 本机宿主补丁 | 已有 WRX request-transform-v2 等定制入口 | 单独登记为环境变量，不能当原生兼容证据 |
| 最终输出 | 应为用户看见的助手正文，可能受主聊天配置影响 | 只在输出侧消费，不尝试撤销/重做上下文编排 |

**当前结论：已通过本机模块级隔离对照，WRX 编排开/关均未因加载 VOICE 改变请求消息，最终正文选择一致；完整宿主与日常配置的兼容性尚待端到端验收。**

不采用请求 `llm/stream` 拦截来抓语音文本，因为它属于请求/模型调用层，可能包含后台调用、工具步骤和非最终回复。DSH 输出接口也必须检查会话归属、消息身份和终止状态。

后续验收至少分为：

1. 隔离、未打 WRX 补丁的同版本 DSH：VOICE 独立工作，关闭 VOICE 不改变聊天请求与事件正文。
2. 隔离的 LEASE-WRX + 所需补丁组合：分别关闭/开启 WRX 请求编排，VOICE 选出的朗读正文均与最终 UI 一致。
3. 两组都覆盖工具续轮、取消、模型重试、压缩、切换会话、多窗口和后台会话排除；确认 VOICE 不注册请求变换、不改消息或预设。
4. 上述通过后才安排日常宿主安装验收；本任务不修改或重启日常 DSH。

证据来源为本机只读核对：

- `node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-client-ui-chat/lib/types/client/contract/slots.d.ts`：助手操作栏接收 messageId。
- 同一安装树的 `dsh-session/lib/types/index.d.ts`、`types.d.ts`：session/event、助手分 step 消息、interrupted 与回合结束。
- `LEASE-WRX/app/index.js`：现有 WRX 也监听 session/event，且排除 parentSession；输出监听本身独立于请求编排，实际兼容证据来自本项目 tests/dsh.test.mjs 的隔离对照。
- 本机 `LEASEDSH-patches/verify-core.mjs` 与 agent-loop 实现：WRX 请求边界定制与原生接口应分开识别。

这些路径均相对其各自背景项目，不属于本项目源码。当前没有与干净上游包逐字节比较，接口来源结论限于包内声明与现有集成证据。

## 5. 第二阶段：ESP32 扩展与固件

先按第一阶段真实音频产物确定最小设备能力，再实现固件。插件增加“扩展”页面：添加/配对设备、在线状态、音量、测试播放、输出目标选择和解除配对。默认仍为浏览器输出；首轮设备适配先支持一个个人设备。

建议设备通过 Wi-Fi 主动连接插件，控制通道用 WebSocket、音频用经授权 HTTP 拉取。用户体验是插件推送播放任务；设备拉取文件可以避免要求浏览器直接访问局域网设备。协议尚未定稿，需先验证 DSH 的 WebSocket 注册、认证与部署方式，不预设无需额外适配即可使用。

板子只保存 Wi-Fi 与设备凭据，不保存 TTS provider 密钥。设备凭据与 DSH 登录 token 分离；配对时由已认证 UI 短期授权，后续可撤销。设备音频 URL 短期有效并绑定设备/任务；断线不默认重播已完成旧任务。

设备握手上报协议版本、固件版本、支持的 codec/采样率/声道、屏幕与资源能力。音频只选择双方支持的格式；不兼容时明确报错或由已实现的转换器转换，禁止直接假定浏览器能播的格式 MCU 都能播。

控制消息预留：hello/capabilities、play、stop、volume、heartbeat、ack、playback-status、error；使用 taskId 关联，ack 接受不等于实际播放完成。具体字段、超时、幂等、版本协商、取消和错误码在固件开工前形成 shared/protocol 的正式 schema。

设备须能访问插件地址。当前本机 DSH 的 LAN/Tailscale 路由是部署背景，不自动成为板子连接配置；设备不能复用浏览器登录状态，TLS/证书与网络可达性需独立验收。

硬件名称可能为 `ESP32-S3-WROOM-1-N16R8`：官方资料对应 16 MB Flash、8 MB PSRAM，支持 2.4 GHz Wi-Fi 与 Bluetooth LE。它不能单独确定开发板的屏幕、音频器件或引脚，也不能把 BLE 当作传统 A2DP 音箱功能。依据：[乐鑫模组数据手册](https://documentation.espressif.com/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)、[ESP32-S3 官方介绍](https://www.espressif.com/en/products/socs/esp32-s3)。

固件前置清单：实物型号、原理图或商品资料、屏幕控制器/分辨率/接口、麦克风与功放型号、I2S/SPI 引脚、供电、Flash/PSRAM 实际识别、USB 烧录方式。未确认前不生成“可直接烧录”的板级配置。BLE 配网不是本阶段音频链路的前置条件。

验收：配对与撤销、真实扬声器播放、音量/停止、断网重连、任务不重复、错误可见、provider 密钥不下发；协议模拟器通过不等于实物验收通过。

## 6. 第三阶段：动态表情

本机安装清单已核实 `dsh-meme@0.1.71`、`dsh-pet@0.3.8`。meme 包含表情资源目录，pet 清单说明包含 WebM 播放资源；当前只核对包清单及目录，未复制素材、未验证动画解码，也未审阅每份素材授权。

保留来源、作者、许可证/授权与转换记录；代码包标注 MIT 不能自动证明所有第三方素材可再分发。先选择少量可用素材，按实际屏幕分辨率、帧率、色深、内存和 Flash 预算转换。浏览器 WebM 动作不直接嵌入 MCU；必要时离线转换为适合屏幕的帧资源并测量大小与播放性能。

第一版表情只按 idle、合成等待、speaking、error 等已有状态联动，用户可手动选择。若以后要按回复内容选表情，另立需求，不偷偷加入提示词或额外 LLM。

验收：设备上动态播放、音频与屏幕并行稳定、资源包版本和校验、素材来源可追溯；只有桌面预览不能算完成。
